## 1. 一句话说清它是什么

**把一份文档切成小段，全部变成向量存起来；用户提问时，先把问题也变成向量，找出最像的几段，再把这几段连同问题一起交给大模型，让它"看着资料回答"。**

这个套路叫 **RAG**（Retrieval-Augmented Generation，检索增强生成）。

它解决的是大模型的两个硬伤：

| 问题 | RAG 怎么解决 |
|---|---|
| 模型不知道你的私有文档 | 把文档片段塞进 prompt，临时"喂"给它 |
| 模型会编（幻觉） | 强制它只依据片段回答，并标注来源 |

## 2. 整体架构：两个阶段

这个项目最重要的结构特征：**分成"离线"和"在线"两个阶段，两者的成本和时间完全不同。**

```
═══════════ 离线阶段：建索引（只跑一次） ═══════════

  data/sample.txt  (2053 字)
        │
        │  ① ingest.py 读文件
        ▼
  原始文本字符串
        │
        │  ② chunk_text() 切分
        ▼
  6 个片段 ["第一条...", "第四条...", ...]
        │
        │  ③ embed() 调 embedding API（花钱、花时间）
        ▼
  index/vecs.npy     6 × 1024 的浮点数矩阵（向量）
  index/chunks.json  6 段原文（文字）
        │
        └── 落盘，以后的每次提问都直接复用


═══════════ 在线阶段：回答问题（每次提问都跑） ═══════════

  用户输入 "实习补贴每天多少钱？"
        │
        │  ① embed() 把问题变成 1 × 1024 向量（1 次 API 调用，很快）
        ▼
  问题向量 q
        │
        │  ② retrieve()：vecs @ q 一次矩阵乘法
        ▼
  6 个相似度分数 [0.31, 0.87, 0.42, ...]
        │
        │  ③ argsort 取 top-4
        ▼
  4 段最相关的原文
        │
        │  ④ answer()：拼成 prompt，调 chat API
        ▼
  回答文本 + 引用的片段编号 [1][2]
```

### 为什么必须分两个阶段

因为**成本差了三个数量级**。

| | 离线建索引 | 在线回答一次 |
|---|---|---|
| 调用次数 | 文档片段数（6 次） | 2 次（1 次 embedding + 1 次 chat） |
| 输入 token | 全文 2053 字 | 问题 + 4 段片段 ≈ 2000 字 |
| 耗时 | 10–30 秒 | 2–5 秒 |
| 频率 | 文档变了才跑 | 每次提问都跑 |

如果每次提问都重新把文档向量化一遍，用户要等 30 秒，API 账单会翻几十倍。**把不变的计算提前算好存起来**——这是工程上最基本的一条优化，也是这个项目第一个值得讲的决策。

## 3. 文件职责地图

```
rag-demo/
├── rag.py              核心逻辑（被所有其他文件调用）
├── ingest.py           离线：建索引
├── app.py              在线：网页界面
├── eval.py             离线：评测检索质量
├── run.bat             启动脚本（Windows 专用）
│
├── data/sample.txt     原始文档
├── index/              索引产物
│   ├── chunks.json       切好的片段原文
│   └── vecs.npy          片段对应的向量
│
├── eval/questions.csv  评测集（问题 + 期望关键词）
├── requirements.txt    依赖清单
├── .env                你的密钥（不进仓库）
├── .env.example        密钥模板（进仓库）
└── .gitignore          哪些文件不进仓库
```

| 文件 | 干什么 | 谁调用它 | 什么时候跑 |
|---|---|---|---|
| `rag.py` | 定义 6 个核心函数 | 其他三个文件都 import 它 | 被调用时 |
| `ingest.py` | 读文档 → 建索引 | 手动执行 | 换文档时 |
| `app.py` | 网页界面 | `streamlit run` 启动 | 每次打开网页 |
| `eval.py` | 算命中率 | 手动执行 | 改完检索策略时 |
| `run.bat` | 设环境变量 + 启动 | 双击 | 每次启动服务 |

**关键理解**：`rag.py` 是唯一的"大脑"，另外三个文件都是"外壳"。改逻辑只改 `rag.py`，界面和脚本不用动。

## 4. 环境依赖：哪段代码需要什么

项目里的代码对环境的依赖是**分层**的。

### 4.1 依赖总表

| 代码 | 需要的库/服务 | 需要网络 | 需要 GPU |
|---|---|---|---|
| `chunk_text()` | 仅 Python 标准库 `re` | 否 | 否 |
| `embed()` | `numpy` + `openai` + **API Key** | 是 | 否 |
| `retrieve()` | `numpy`（内部会调 `embed`） | 是 | 否 |
| `answer()` | `openai` + **API Key** | 是 | 否 |
| `read_pdf()` | `pypdf` | 否 | 否 |
| `load_document()` | `pathlib` | 否 | 否 |
| `ingest.main()` | 上面全部 + `python-dotenv` | 是 | 否 |
| `app.py` 全部 | `streamlit` + 上面全部 | 是 | 否 |
| `eval.py` | `csv` + `rag.py` | 是 | 否 |
| `run.bat` | Windows 命令行 | 否 | 否 |

**结论：这个项目完全不需要 GPU、不需要 PyTorch、不需要 CUDA。** 所有重型计算都在云端 API 上。本机只负责切字符串、算矩阵乘法（6×1024，微不足道）、发 HTTP 请求。

### 4.2 为什么 `pypdf` 是"按需"的

```python
def read_pdf(path: Path) -> str:
    from pypdf import PdfReader   # ← 注意这行在函数内部
    ...
```

`import` 写在函数里，叫**延迟导入**。好处是：只处理 `.txt` 时，`pypdf` 装不装都不影响其他功能。

同理，`rag.py` 里的 `OpenAI(...)` 也是延迟创建的（在 `get_client()` 里），所以没有 API Key 时 `import rag` 也不会报错——方便离线测试。

### 4.3 环境变量：配置不写死在代码里

`.env` 里有 4 个变量，`rag.py` 启动时读取：

```python
load_dotenv()                                    # 读 .env 到 os.environ

EMBED_MODEL = os.getenv("EMBED_MODEL", "BAAI/bge-m3")
CHAT_MODEL  = os.getenv("CHAT_MODEL", "Qwen/Qwen2.5-7B-Instruct")
BASE_URL    = os.getenv("BASE_URL", "https://api.siliconflow.cn/v1")
```

| 变量 | 作用 | 改了会怎样 |
|---|---|---|
| `API_KEY` | 身份认证 | 缺了报 401 |
| `BASE_URL` | 调用哪个平台的接口 | 换平台必须改，否则 404 |
| `EMBED_MODEL` | 用哪个模型做向量化 | **改了就冲突**（见下） |
| `CHAT_MODEL` | 用哪个模型生成回答 | 随便换，只影响回答质量 |

> **`EMBED_MODEL` 换了必须重建索引。** 不同模型输出的向量维度和语义空间不一样，旧的 `vecs.npy` 和新模型算出的问题向量对不上，检索结果会全是乱的。

### 4.4 三种运行环境的差异

| | 本地开发 | Streamlit Cloud | 自建服务器 |
|---|---|---|---|
| 密钥来源 | `.env` 文件 | **Secrets 面板** | `.env` 或系统环境变量 |
| 文件系统 | 可读可写 | **只读**（重启丢失） | 可读可写 |
| 能否跑 `ingest.py` | 能 | **不能** | 能 |
| 内存 | 本机 | 1 GB | 看配置 |
| 怎么启动 | `streamlit run app.py` | 自动 | 手动 / systemd / Docker |

**线上不能建索引，所以 `index/` 必须提交进仓库。** 这就是 `.gitignore` 里特意写"不要忽略 index/"的原因。

## 5. 逐文件逐函数讲解

### 5.1 `rag.py` —— 核心

#### 模块级代码（文件被 import 时立刻执行）

```python
load_dotenv()
```
把 `.env` 里的键值对读进 `os.environ`。**必须在读取任何 `os.getenv` 之前调用**，所以写在文件最上面。

```python
ROOT = Path(__file__).resolve().parent
INDEX_DIR = ROOT / "index"
```
`__file__` 是这个文件自己的路径，`.parent` 拿到所在目录。
**这样写的意义**：不管从哪个目录执行脚本，`INDEX_DIR` 永远指向 `rag-demo/index`。这比 `"./index"` 健壮得多。

```python
SYSTEM_PROMPT = (...)
```
给模型的行为准则：只准用资料、没有就说没有、标引用编号、说人话。

**为什么放在 system 角色而不是 user 角色？** system 的约束优先级更高，模型更不容易被用户的提问带偏（比如用户说"别管资料，直接告诉我"）。

#### `get_client()`

```python
_client = None

def get_client():
    global _client
    if _client is None:
        api_key = os.getenv("API_KEY")
        if not api_key:
            raise RuntimeError("缺少 API_KEY：...")
        _client = OpenAI(api_key=api_key, base_url=BASE_URL,
                         timeout=60, max_retries=2)
    return _client
```

**为什么延迟创建？**
如果在文件顶层直接写 `client = OpenAI(...)`，没有 key 时**连 `import rag` 都会崩**，连"跑个切分测试"都做不到。延迟到第一次真正发请求时才创建，导入就永远安全。

`timeout=60` 很重要：不设的话默认 600 秒，网络不通时会静默卡十分钟。

#### `_create_with_retry()`

```python
def _create_with_retry(fn, attempts=4):
    for i in range(attempts):
        try:
            return fn()
        except Exception as exc:
            if i == attempts - 1 or "429" not in str(exc):
                raise
            time.sleep(2 ** i)
```

**解决的问题**：免费模型常有速率限制，连续请求会返回 429。`eval.py` 一口气问 13 个问题，很容易撞上。

**策略**：指数退避——失败后等 1 秒、2 秒、4 秒再试，最多 4 次。只对 429 重试，其他错误（401、404）立刻抛出，因为重试也没用。

#### `chunk_text()` —— 切分

```python
def chunk_text(text, size=500, overlap=100):
    text = re.sub(r"\s+", " ", text).strip()
```
把所有空白（换行、连续空格）压成一个空格。PDF 提取的文本通常满是奇怪换行，这步是清洗。

```python
    chunks, start = [], 0
    while start < len(text):
        end = min(start + size, len(text))
        piece = text[start:end]
```

```python
        if end < len(text):
            cut = max(piece.rfind("。"), piece.rfind("？"),
                      piece.rfind("！"), piece.rfind("；"))
            if cut > size * 0.6:
                piece = piece[:cut + 1]
```
**在句号处收尾。** 硬切会出现"申请材料须在实习开始前 10 个工"这样的半句话。
`cut > size * 0.6` 是阈值：只在句子出现在窗口后 40% 时才截断，否则片段太短、信息量不够。

```python
        step = len(piece) - overlap
        start = start + step if step > 0 else end
```
**这是全项目最容易写错的一行。**
如果按固定 `size` 前进，当句子截断导致 `piece` 变短时，会有一段文字既不在当前片段、也不在下一个片段——**检索永远找不到它**。
正确做法：按"实际产出了多少字"前进，保证相邻片段之间始终有 `overlap` 个字的真正重叠。

**参数怎么定：**

| 参数 | 默认 | 调大 | 调小 |
|---|---|---|---|
| `size` | 500 | 上下文完整，检索变粗、token 变贵 | 检索变准，答案易被切断 |
| `overlap` | 100 | 边界更安全，索引变大 | 省空间，跨段答案易丢 |

中文 500 字 ≈ 350 token；4 段拼起来约 1400 token，成本和效果比较平衡。

#### `embed()`

```python
def embed(texts, batch_size=16):
    ...
    for i in range(0, len(texts), batch_size):
        batch = [t if t.strip() else " " for t in texts[i:i + batch_size]]
        resp = _create_with_retry(
            lambda b=batch: client.embeddings.create(model=EMBED_MODEL, input=b))
        vectors.extend(item.embedding for item in resp.data)
```

- **批处理**：一次发 16 条，比一条条发快得多
- **空字符串兜底**：API 对空字符串会报错，替换成一个空格
- **`lambda b=batch`**：Python 闭包陷阱——lambda 里的循环变量延迟绑定，不加 `b=batch` 所有请求都会用最后一批数据

```python
    arr = np.asarray(vectors, dtype=np.float32)
    norms = np.linalg.norm(arr, axis=1, keepdims=True)
    norms[norms == 0] = 1.0
    return arr / norms
```
**归一化，是检索正确性的基础。**

把每个向量缩放到长度为 1，之后两个向量做**点积**，结果就等于**余弦相似度**：

```
cos(a, b) = (a · b) / (|a| × |b|)
```

因为 `|a| = |b| = 1`，分母为 1，点积直接就是余弦值。检索时一次矩阵乘法搞定，不用每条都算除法。

#### `build_index()` / `load_index()`

```python
def build_index(chunks, index_dir=INDEX_DIR):
    vecs = embed(chunks)
    np.save(index_dir / "vecs.npy", vecs)
    (index_dir / "chunks.json").write_text(
        json.dumps(chunks, ensure_ascii=False), encoding="utf-8")
```

存两个文件，因为它们是**两种不同的数据**：

- `vecs.npy`：二进制浮点矩阵，`numpy.save` 效率最高，人类读不了
- `chunks.json`：文本，必须用 UTF-8，`ensure_ascii=False` 让中文原样写入

```python
def load_index(index_dir=INDEX_DIR):
    if not chunks_path.exists() or not vecs_path.exists():
        raise FileNotFoundError(f"索引不存在：{index_dir}，请先运行 python ingest.py")
```
抛**带中文提示的** `FileNotFoundError`，是为了让 `app.py` 能捕获它、显示友好页面，而不是给用户看红色堆栈。

#### `retrieve()` —— 检索

```python
def retrieve(query, chunks, vecs, k=4):
    k = min(k, len(chunks))
    q = embed([query])[0]
    scores = vecs @ q
    top = np.argsort(scores)[::-1][:k]
    return [(chunks[i], float(scores[i])) for i in top]
```

**`vecs @ q` 是核心中的核心。**
`vecs` 是 6×1024，`q` 是 1024，矩阵乘向量 → 6 个数字，每个是"问题与这一段的余弦相似度"。**一次运算，全部算完。**

`np.argsort(scores)` 返回从小到大排序后的下标，`[::-1]` 反转成从大到小，`[:k]` 取前 k 个。

`k = min(k, len(chunks))`：文档只有 6 段时，用户把滑块拖到 10 也不会越界。

#### `answer()` —— 生成

```python
context = "\n\n".join(f"[{i}] {c}" for i, (c, _) in enumerate(hits, 1))
```
拼成带编号的形式：

```
[1] 第八条 学校对参加校外实习的学生发放实习补贴……
[2] 第九条 补贴按月发放……
```

编号不是装饰——它让模型能说"根据 [1]"，用户能点开核对。**这是抑制幻觉最便宜的手段。**

```python
messages = [
    {"role": "system", "content": SYSTEM_PROMPT},
    {"role": "user",   "content": f"资料：\n{context}\n\n问题：{query}"},
]
```

```python
temperature=0.3
```
0 最确定、1 最发散。问答要稳定，用 0.3。

```python
max_tokens=800
```
硬性上限，防止模型长篇大论烧钱。

### 5.2 `ingest.py` —— 建索引

```python
SUPPORTED = {".pdf", ".txt", ".md"}
```
支持三种格式。想加 `.docx` 就在这里加，并在 `load_document` 里加分支。

```python
def load_document(path):
    suffix = path.suffix.lower()
    if suffix == ".pdf":  return read_pdf(path)
    if suffix in {".txt", ".md"}: return path.read_text(encoding="utf-8", errors="ignore")
```
`errors="ignore"`：遇到无法解码的字节就跳过，而不是整个崩掉。

```python
def pick_document():
    candidates = sorted(p for p in DATA_DIR.glob("*") if ...)
    if not candidates: raise SystemExit(...)
    return candidates[0]
```
**默认取按文件名排序的第一个。** 便利也是坑——`data/` 里同时有 `sample.txt` 和你的 PDF 时可能选错。**要处理指定文件，直接 `python ingest.py data/xxx.pdf`。**

```python
if len(text) < 300:
    raise SystemExit("提取到的文字太少，可能是扫描版 PDF（整页是图片）……")
```
**这个检查非常值得学。** 扫描版 PDF 的 `extract_text()` 返回空字符串，不检查的话会建出一个空索引，然后在网页上问什么都答"资料中未提及"，排查半天。

### 5.3 `app.py` —— 界面

```python
st.set_page_config(page_title="文档问答 Demo", page_icon="📄", layout="centered")
```
**必须是第一个 Streamlit 调用**，否则报错。

```python
try:
    for _key in ("API_KEY", "BASE_URL", "EMBED_MODEL", "CHAT_MODEL"):
        if _key in st.secrets:
            os.environ[_key] = st.secrets[_key]
except Exception:
    pass

```
**这段顺序至关重要。**
线上没有 `.env`，密钥在 Streamlit 的 Secrets 面板里。必须**先把 Secrets 写进环境变量，再 import rag**，否则 `rag.py` 在导入时读不到配置，会一直用默认值。
`except Exception: pass` 是因为本地没有 `secrets.toml` 时访问 `st.secrets` 会抛异常。

```python
try:
    chunks, vecs = load_index()
except FileNotFoundError:
    st.error("还没有建立索引。请在项目目录下先运行：")
    st.code("python ingest.py", language="bash")
    st.stop()
```
`st.stop()` 立刻终止页面渲染。没有它，后面的代码会拿着未定义的 `chunks` 继续跑，报 `NameError`。

```python
@st.cache_resource
def get_index():
    return load_index()
```
`@st.cache_resource` 让索引**只加载一次**。Streamlit 每次交互都会重跑整个脚本，没有缓存的话每次点按钮都要重新读磁盘。

```python
with st.spinner("检索并生成中…"):
    text, hits = answer(query, chunks, vecs, k=k)
```
`st.spinner` 是等待动画，`with` 块结束时自动消失。

### 5.4 `eval.py` —— 评测

```python
rows = list(csv.DictReader(QUESTIONS.open(encoding="utf-8-sig")))
```
`utf-8-sig` 兼容带 BOM 的 CSV（Excel 另存为时经常加 BOM）。

```python
for k in ks:
    for row in rows:
        hits = retrieve(question, chunks, vecs, k=k)
        if not any(keyword in chunk for chunk, _ in hits):
            missed.append(question)
```
**判定逻辑**：召回的前 k 段里，只要有一段包含期望关键词，就算命中。

这很粗糙，但足以暴露"切分不对""embedding 选错""索引没更新"这类结构性问题。

`for k in ks` 是为了看**命中率随 k 的变化**——k 越大命中率越高，但成本和噪声也越高，要找的是拐点。

### 5.5 `run.bat` —— 启动脚本

```bat
set "USERPROFILE=%~dp0"
set "USERPROFILE=%USERPROFILE:~0,-1%"
set "HOME=%USERPROFILE%"
```
`%~dp0` 是 bat 文件所在目录（带尾部反斜杠），第二行去掉那个反斜杠。

**为什么改 `USERPROFILE`？**
Streamlit 默认把配置写到 `C:\Users\<用户名>\.streamlit`。如果用户目录没有写权限，启动就报 `Permission denied`。把 `USERPROFILE` 指到项目目录，它就写进 `rag-demo\.streamlit`。

`HOME` 也要设，因为 Python 的 `expanduser("~")` 在 Windows 上会读 `HOME`。

```bat
set "PYTHONUTF8=1"
```
强制 Python 用 UTF-8 输出，避免控制台中文乱码。

```bat
python -u -m streamlit run app.py
```
- `-u`：不缓冲输出，日志立刻显示
- `-m streamlit`：用"当前这个 Python"的 streamlit，而不是 PATH 里随便哪个

## 6. 关键设计决策

### ① 为什么不用向量数据库

> 6 个片段，向量矩阵是 6×1024 的 float32，约 24 KB。`vecs @ q` 是微秒级。
> 引入向量库只会增加部署复杂度、多一个故障点，收益为零。
> 什么时候该换：片段超过十万级、需要按元数据过滤、需要增量更新和持久化时——那时矩阵乘法要算 10 万×1024，内存和延迟都开始成为问题。

### ② 为什么切 500 字 / 重叠 100 字

> 中文 500 字约 350 token，4 段拼进 prompt 约 1400 token，成本和上下文长度平衡。
> 重叠 100 字是防止答案刚好落在切口上。
> 代码在句号处收尾，代价是实际长度在 300–500 之间浮动。
> 太小（200）会丢上下文，太大（1000）检索精度下降且费 token。

### ③ 为什么归一化

> 归一化后向量长度为 1，点积直接等于余弦相似度，省掉每次的除法。
> 更重要的是：余弦相似度只看方向不看长度，而文本向量长度受文本长短影响——不归一化的话，长片段会因为向量的模更大而占便宜。
> 补充：归一化之后，余弦和欧氏距离的排序完全等价（`‖a−b‖² = 2 − 2a·b`），选余弦只是为了少一次开方，不是更准。

### ④ 为什么 k=4

> 太少（1–2）信息不全，模型答不完整；太多（8+）会稀释注意力，模型容易抓错重点，token 成本也线性上升。
> 4 是这个规模的甜点。真实项目应该用 eval 扫一遍 k=1,2,4,8 找拐点，而不是拍脑袋。

### ⑤ 为什么把 index/ 提交进仓库

> 线上（Streamlit Cloud）的文件系统是只读的，不能跑 `python ingest.py`。
> 所以索引必须在本地建好、随代码一起提交，线上直接读。
> 代价是文档更新后要重新建索引并重新 push——这对 demo 可接受，对生产不可接受（生产会用对象存储 + 启动时拉取，或直接上向量数据库）。

### 7.2 Streamlit Community Cloud 部署步骤

1. 打开 <https://share.streamlit.io>，用 **GitHub 账号**登录

API_KEY = "sk-你的key"

### 7.4 国内访问的备选方案

`streamlit.app` 在国内经常很慢或打不开。备选：

1. **魔搭 ModelScope 创空间**：免费、国内直连，支持 Streamlit 应用

3. **HuggingFace Spaces**：功能一样，国内访问同样不稳定

三种方案代码**完全不用改**，只换运行环境。

## 8. 常见改动怎么做

### 换文档

```bash
# 方式一：放到 data/ 再跑（注意会按文件名排序取第一个）
python ingest.py

# 方式二：直接指定（推荐）
python ingest.py data/我的手册.pdf
```

### 换模型平台

只改 `.env` 里的 `BASE_URL` 和两个模型名，代码一行不动。**换 `EMBED_MODEL` 必须重建索引。**

### 调切分参数

改 `rag.py` 里 `chunk_text` 的默认值，或在 `ingest.py` 调用时传参，然后**必须重新建索引**。

### 加 rerank（性价比最高的升级）

思路：先取 top-10，再用重排模型精排取 4。

```python
# 伪代码
hits = retrieve(query, chunks, vecs, k=10)
pairs = [(query, chunk) for chunk, _ in hits]
scores = rerank_api(pairs)          # bge-reranker
top4 = sorted(zip(hits, scores), key=lambda x: -x[1])[:4]
```

改完跑 `eval.py`，对比命中率，把数字写进 README。

### 加文件上传

`app.py` 里加：

```python
uploaded = st.file_uploader("上传文档", type=["pdf", "txt", "md"])
```

然后在上传后现场解析、切分、`embed()`（注意：这会实时消耗 API，且线上内存有限）。

## 9. 排错手册

| 报错 | 根因 | 解决 |
|---|---|---|
| `ModuleNotFoundError: rag` | 不在项目目录 | `cd` 到项目目录 |
| `缺少 API_KEY` | `.env` 没建/没填 | 复制 `.env.example` |
| `401 Unauthorized` | key 错，或文件成了 `.env.txt` | 检查文件名 |
| `404 model not found` | 模型名/`BASE_URL` 错 | 去平台复制准确 ID |
| `429 Too Many Requests` | 免费额度限流 | 已内置退避重试；降低频率 |
| `提取 0 字` | 扫描版 PDF | 换文本版或先 OCR |
| 页面"索引不存在" | 没跑 `ingest.py` | 先建索引 |
| 线上"索引不存在" | `index/` 没提交 | `git add index/` |
| `Permission denied: .streamlit` | 用户目录不可写 | 用 `run.bat`（改 `USERPROFILE`） |
| `Address already in use` | 8501 被占 | `--server.port 8502` |
| 中文乱码 | 控制台 GBK | `chcp 65001` 或 `PYTHONUTF8=1` |
